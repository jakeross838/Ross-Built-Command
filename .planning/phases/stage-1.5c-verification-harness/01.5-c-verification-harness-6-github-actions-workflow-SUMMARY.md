## Decisions Made

- **Wire 3 additional GH secrets per Rule 2 (missing-critical):** Plan 6's PLAN.md template listed only `ANTHROPIC_API_KEY` + `VERCEL_TOKEN` in `env:`. But `src/lib/verification/auth-strategy.ts:81` requires `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and `auth-strategy.ts:86` requires `HARNESS_FIXTURE_PASSWORD`. Without these, the harness throws `[auth-strategy] HARNESS_FIXTURE_PASSWORD env var is missing` and exits with code 4 — defeating the entire workflow. Added all 3 to the workflow `env:` block; documented in README. SETUP-COMPLETE.md noted ANTHROPIC + VERCEL secrets present but did not pre-stage the 3 Supabase/HARNESS secrets — flagged for Jake at halt review.
- **Add explicit "Wait for Vercel preview Ready" step:** The plan template did not include this step but watchpoint #2 explicitly required it. The harness's own `vercel-discovery.ts` would otherwise either return a not-yet-Ready URL or fail discovery entirely. Adding the workflow-level wait gives the harness a known-Ready URL via `--preview-url` arg, which the harness then echoes back through `preview_url_source: "explicit"` in the report.
- **Add explicit "Parse harness JSON output" step:** Watchpoint #4 required robustness to malformed stdout. The PR comment uses `final.md` (sanitized), not the JSON, but the JSON is uploaded as artifact and Plan 9 custodian sweep will consume it. Adding a workflow-level JSON-validity check gives early signal if `report-writer.ts` ever changes the stdout format. Defense in depth.
- **Use Node inline parser instead of jq:** The actions/setup-node@v4 image has both `jq` and `node` available, but the project canonical script runner is `tsx` and Node is universal. Inline `node -e` keeps dependencies minimal and matches Plan 5's TypeScript-everywhere posture.
