## Specific Ideas

### Vision API criteria contract (per D-17 + Plan-review watchpoint #4)

PLAN files going forward must include a `criteria:` block. Recommended yaml-style format:

```yaml
criteria:
  mechanical:
    - "npm run build clean (0 warnings)"
    - "npx tsc --noEmit returns 0 errors in src/"
  dom:
    - "Page /financials/bills/[id] contains <th>Cost Code</th>"
    - "Each invoice line item row has a non-empty cost-code cell"
  visual:
    - "Site Office signature visible: tracking-eyebrow 0.18em UPPERCASE on eyebrows"
    - "Slate palette only — no off-token hex"
  behavioral:
    - "Clicking Approve transitions invoice status to pm_approved"
    - "Cost code dropdown filters by org_cost_codes.is_active = true"
  semantic:
    - "Cost code is visible on each line item (Layer 3 vision)"
    - "Document Review pattern: file preview LEFT, right-rail panel, audit timeline BELOW"
```

`mechanical` + `dom` map to Layer 1; `visual` + `semantic` map to Layer 3; `behavioral` maps to Layer 2 (state machines / transitions / workflow).

### Idempotency key shape (per D-22)

```
idempotency_key = sha256(commit_sha + canonical_criterion_hash)
canonical_criterion_hash = sha256(JSON.stringify({phase, plan, criterion_category, criterion_text}))
```

Stored at `.planning/verification/runs/[phase]/[commit]/idempotency.json`. Layer 3 vision call cache check: if key exists with `result: PASS` and same input shape, skip the API call and reuse cached verdict.

### Loop-with-executor state machine (per D-05/D-06/D-07)

```
state: idle | running-layer-1 | running-layer-2 | running-layer-3 | failed-fixable | failed-ambiguous | passed
transitions:
  idle → running-layer-1 (commit pushed, Vercel preview ready)
  running-layer-1 → failed-fixable (Layer 1 error with file:line) | running-layer-2 (Layer 1 pass)
  running-layer-2 → failed-fixable (rule violation) | running-layer-3 (Layer 2 pass)
  running-layer-3 → failed-fixable (clear FAIL with confidence ≥ 0.7) | failed-ambiguous (PASS or FAIL with confidence < 0.7) | passed
  failed-fixable → spawn gsd-fix-executor → idle (after fix commit lands; iter++)
  failed-ambiguous → halt-for-Jake
  iter == 3 → halt-for-Jake (regardless of fixable/ambiguous)
```

### Standards JSON schema (per D-02 + Plan-review watchpoint #1)

```json
{
  "$schema": ".planning/verification/standards/_schema.json",
  "id": "conservation-money-line-items-sum",
  "domain": "conservation",
  "title": "Line items must sum to total amount",
  "description": "Sum of invoice.line_items[*].amount must equal invoice.total_amount within 1 cent tolerance",
  "verifyFn": "conservationMoneyLineItemsSum",
  "applies_to": ["invoice", "draw", "change_order"],
  "severity": "blocking",
  "source": ["GAAP — basic accounting identity"],
  "tags": ["money", "conservation", "line-items"]
}
```

`verifyFn` resolved at runtime via registry: `import { registry } from '@/lib/verification/registry'`. Adding a new rule = drop a JSON file + register one function in registry.
