## Decisions Made

### 1. SubNavDropdown helper instead of NavDropdown surface-variant retrofit

**Context:** Plan's `interfaces` section specifies `More ▾ dropdown reuses existing NavDropdown component (hybrid hover+click + keyboard navigation)`. Direct reuse of NavDropdown would render invisible text on the light sub-nav surface because NavDropdown hard-codes white-sand foreground (`text-[#F7F5EC]` and `text-[rgba(247,245,236,0.65)]`) tuned for the dark top-nav background.

**Options considered:**
- (a) Add a `surface` variant prop to NavDropdown — blocked by post-edit hook because nav-dropdown.tsx contains 4 pre-existing hex literals at lines 167, 168, 319 (the dark-nav-tuned rgba/hex foreground) that the hook flags on any edit to the file.
- (b) Wrap NavDropdown in a parent CSS scope that overrides its colors — would require `!important` or `:global` overrides because NavDropdown hard-codes its own classNames; brittle.
- (c) Build SubNavDropdown helper that mirrors NavDropdown's behavior (hybrid hover+click + keyboard nav + click-outside-to-close + focus management) using Site Office tokens — clean, no scope-creep edits to NavDropdown, preserves the plan's intent (same UX behavior).

**Chosen: (c).** Documented with full rationale in per-job-tabs.tsx top-of-file comment. The plan's must_haves describes UX behavior reuse, not literal code reuse — the SubNavDropdown helper satisfies the UX contract.

**Rule classification:** Rule 4 candidate (architectural decision) but the alternative (retrofit NavDropdown) reached into scope-boundary territory (pre-existing hex literals in unrelated file). Chose the in-scope path. NavDropdown is unchanged.

### 2. activity/page.tsx full replacement

**Context:** Plan 5 lists `/jobs/[id]/activity/page.tsx` in files_modified. The prior implementation (post-Plan 3) retained client-side Supabase auth + JobFinancialBar + Breadcrumbs + custom "Activity log coming soon" card. Plan 5 says replace with NwPlaceholderCard ~30 LOC.

**Chosen:** Full replacement per plan strict spec. Prior implementation preserved as backup snapshot comment in the file header for F1 reference when wiring the per-job activity_log filter.

### 3. _params naming convention for unused route params

**Context:** Placeholder routes don't use `params.id` (deferred to F1+). ESLint rule `/^_/u` requires unused args to be prefixed.

**Chosen:** Renamed `params` to `_params` in 19 placeholder handlers. The type signature `params: { id: string }` is preserved for Next.js typing.
