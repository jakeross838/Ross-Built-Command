## Decisions Made

1. **`Layer2Context` re-exported from `../types` rather than locally redefined.** Plan code text under `<interfaces>` showed both an import-from-types and a local interface block. ARCH-CRIT-3 + Jake's watchpoint #1 forbid the local form; the import form was used in `runner.ts` and `index.ts`. Plan 2 set this precedent for `Layer1Context`; Plan 3 mirrors exactly. Verification: `grep -nE '^(export )?(interface|type) Layer2Context' src/lib/verification/layer2/**/*.ts` returns 0.

2. **`verifyFn` signature kept narrow — `VerifyFnContext` does NOT carry `org_id` directly.** `Layer2Context.org_id` flows through `runner.ts` to `deriveIdempotencyKey()` at the runner level, not to the verifyFn itself. The first rule (`conservationMoneyLineItemsSum`) doesn't need tenant identity (it HEAD-probes a URL only). If a future rule needs to do org-scoped DB lookups, that's a Plan 1 amendment to `VerifyFnContext` — kept narrow today per YAGNI.

3. **SKIP-on-throw in runner.ts.** When `resolveVerifyFn(rule.verifyFn)` throws (unregistered ID — typo in JSON file or missing `import` line in `index.ts`) or when the verifyFn itself throws, the runner emits a SKIP VerificationResult with the error message in `error` field. The state machine reads SKIP as loop-progresses. Alternative (FAIL) would block dispatch on a registry typo and produce a confusing failed-fixable transition for a config error.

4. **`validateRule()` short-circuits on missing required fields.** Early `return { valid: false, errors }` after the required-fields loop prevents cascading false-positives (e.g., a missing `id` would also trigger `id must be string`). Cleaner stderr output when a JSON file is malformed.

5. **`loader.ts` skips entries starting with `.` or `_`.** Covers `_schema.json` (which lives at `.planning/verification/standards/_schema.json` — at the standards root, not under a domain dir, but defensive), `.gitkeep` (Plan 1 scaffolding), `.DS_Store`, and any future `_shared/` helper dirs without enumerating.

6. **Phase-placeholder PASS branch retained in `money-line-items-sum.ts`.** Plan code shipped both a SKIP-when-no-introspection block AND a PASS-when-walker-not-implemented branch. Kept both so that if `/api/_introspect/*` ships unexpectedly between now and the next harness rerun, the rule reports cleanly (PASS with todo note) rather than silently mis-reporting "no surface".

7. **`ValidationResult` type re-exported from `index.ts`.** Consumers (Plan 5 orchestrator, Plan 11 self-test) can introspect `validateRule` errors without reaching into `./loader`. Cross-layer contract types stay in `types.ts`; layer-internal types are re-exported through the barrel.
