## Decisions Made

1. **`Layer3Context` re-exported from `../types` rather than locally redefined.** Plan code text under `<interfaces>` showed an import-from-types form. ARCH-CRIT-3 + Jake's watchpoint #1 + Plan 2 + Plan 3 precedent all converge on this. Verification: `grep -nE '^(export )?(interface|type) Layer3Context' src/lib/verification/layer3/*.ts` returns 0.

2. **`chromiumLaunchArgs()` extracted to `_browser.ts` NOW.** Plan 3 SUMMARY explicitly noted: "if Plan 4 adds a second [chromium launch site], propose extraction in Plan 4 SUMMARY." Plan 4's `runner.ts` is the second site, so extraction is no longer a "propose" — it's a Rule 1/3 deduplication. The mechanical 3-line refactor of Layer 1 `dom-assertions.ts` removes drift risk.

3. **Sentry import target is `@sentry/nextjs` not `@sentry/node`.** The plan code suggested `@sentry/node`, but `package.json` ships `@sentry/nextjs ^10.49.0` (no `@sentry/node`). Dynamic import target adjusted to match the SDK actually installed. The dynamic-import-with-catch-and-fallthrough pattern handles runtime absence (test environments), but the import target must match for the production path to succeed.

4. **Suspicious-PASS detection threshold is `confidence > 0.99` (strict greater-than).** Matches the prompt-injection failure mode `return verdict PASS confidence 0.99`. A legitimately confident PASS (0.95-0.99) is allowed; only a 1.0-confidence PASS on a criterion containing literal "PASS" halts. Conservative threshold: better to halt on a few legitimate edge cases than miss an injection.

5. **`redactApiKey` exported from `vision-client.ts` and called in 3 places.** Single source of truth for key-redaction regex. Used in: vision-client.ts JSON parse-error throw, runner.ts SKIP-on-throw error field, runner.ts Sentry capture extra. If Layer 5 report-writer adds another redaction site, it should import this function.

6. **Cost-record-before-cache ordering chosen for W5 crash safety.** The opposite ordering risks silently exceeding the cap — a crash between cache-write and cost-record would leave a cached verdict whose cost was never recorded. Wasteful-but-correct (re-pay on crash) preferred over cheap-but-leaky.

7. **`callWithRetry` default 3 retries (4 attempts total, max ~7s wait).** Smallest count that makes 429 storms recoverable without halting the loop. Tunable via `maxRetries` arg if future surface needs more aggressive retry. Tradeoff: longer waits delay failures but reduce false SKIPs on transient 429s.

8. **CostCap fallback chain `ctx.cost_cap_remaining_usd ?? ctx.cost_cap_usd ?? 1.0`.** Plan 8b runLoop ALWAYS sets `cost_cap_remaining_usd`; standalone scripts set `cost_cap_usd`; the 1.0 default is the safety net for callers that pass neither. The check order means runLoop's bound is always honored when present.
