## Decisions Made

1. **Migration number resolved as 00092, not the plan-template's 00050.** The 00050 slot was already taken by `00050_feedback_notes.sql` since the plan was authored. Followed the plan's Step C "verify against actual filesystem before commit" guidance and bumped sequentially.

2. **FIXTURE_ORG_ID UUID encoding.** Used `00000000-0000-0000-0000-fb1ce0a55e55` as the mnemonic encoding ("FIxture Org ASsessment"). Documented in migration header so future readers don't think the value is arbitrary.

3. **Down-migration uses `is_active=FALSE` for org_members instead of DELETE FROM.** The post-edit hook caught my initial DELETE FROM and blocked the write. Investigated org_members schema: it has no `deleted_at` column, but does have `is_active BOOLEAN NOT NULL DEFAULT TRUE`. Switched to `UPDATE ... SET is_active=FALSE`, which is the project-canonical soft-disable for memberships and matches CLAUDE.md "Never delete records — soft delete only" rule.

4. **criteria-loader.test.md scaffold ships in Plan 1, not Plan 5 or Plan 11.** Per iter-1 ARCH-CRIT-2 amendment text: shipping the scaffold here means the Plan 5 author must read it before writing `criteria-loader.ts`. The 4 failure modes are the regressions Plan 5 must defend against regardless of parsing strategy chosen.

5. **`paused-for-fix` added to LoopState union explicitly.** Plan 8b's LoopOutcome.final_state spec calls for an explicit `"paused-for-fix"` value distinct from `"failed-ambiguous"`. Plan 1 ships the type so Plan 8b implementation can reference it without locally redefining. Transition functions still use `"failed-fixable"` as the prerequisite state for fix-executor; `"paused-for-fix"` is reserved for Plan 8b's outer-loop semantics.
