## Decisions Made

1. **types.ts amendment over local Layer1Context redefinition.** Plan code suggested defining `Layer1Context` in `index.ts` with `skip_build` / `skip_typecheck` fields. ARCH-CRIT-3 + Jake watchpoint #1 forbid local redefinition. Resolved by adding the two optional fields to the canonical `types.ts` `Layer1Context` interface. Single source of truth preserved; plan's dev-loop intent honored. Documented in types.ts inline comment.

2. **Threaded `org_id?: string` through every sub-runner signature.** D-30 enforces tenant-bounded idempotency. The Plan 1 `deriveIdempotencyKey()` already defaults `org_id` to `FIXTURE_ORG_ID`, but explicit threading from `runLayer1(ctx)` -> sub-runners makes the tenant boundary visible at every callsite — and prevents future drift if the default ever changes.

3. **Sandbox args helper extracted as `chromiumLaunchArgs()`.** Centralized policy: `--disable-dev-shm-usage` always; `--no-sandbox` only when `CI=true` OR `GITHUB_ACTIONS=true`. Future hardening (e.g., `--disable-blink-features=AutomationControlled`) gets added in one place. Documented as MEDIUM-2 fix in code + README.

4. **Build-warning regex tightened from `/warn[ :]/i` to `/\bwarn(?:ing)?[ :]/i`.** The plan's regex was over-greedy — it would match the substring "warn" inside arbitrary words (e.g., "warning_count", "warned"). Tightened to word-boundary + optional "ing" + space-or-colon to match Next.js's actual warning prefix `warn -` and `Warning:` formats without false-positives on identifiers in stack traces.

5. **`runRouteStatusCheck` criterion ID falls back to "root" when route is "/".** Original plan: `route.replace(/\W/g, "-").replace(/^-+|-+$/g, "")`. For `/` this produces an empty string, leading to a degenerate `"layer1-route-status-"` ID. Added `|| "root"` fallback so the root route gets a stable, distinguishable ID.

6. **Synthetic criterion `phase: "(any)"` / `plan: "(synthetic)"` for mechanical checks.** Build/typecheck/hooks/route-status criteria are inherent to Layer 1, not declared in PLAN-file `criteria:` blocks. Marked them synthetic so they pass through `deriveIdempotencyKey()`'s canonical hash without polluting per-PLAN criterion telemetry.
